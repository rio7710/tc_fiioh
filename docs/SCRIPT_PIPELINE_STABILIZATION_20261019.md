- 자동제작은 `/api/script/generate` 동기 경로, 수동 제작은 `/api/script/jobs` 큐 경로를 사용한다. 전자의 상세 진단 콜백 연결이 빠져 있다.

## 목표 흐름

키워드 확정 → 1차 대본 작성·검증·문장 검수 → 대본 확정 → 공통 콘티 작업 큐 → 구조 검사 → 장소·행동 검사 → 필요한 필드만 보정 → 씬별 검수 → 전체 계약 재검증 → 저장 → 음성·이미지 제작.

씬별 검수 병렬화는 유지한다. 작성 중 스트리밍 검수 도입은 이번 범위에서 제외한다. 실행 경로 통합과 검증 안정화가 먼저다.

## 오류 계약

오류 정보는 `code`, `severity`, `scene_id`, `field_paths`, `evidence`, `repair_scope`, `retryable`로 표현한다. 표시 문장은 분기 기준으로 사용하지 않는다.

| 코드 | 의미 | 처리 |
| --- | --- | --- |
| ASSET_FILE_MISSING | 등록 파일이 실제로 없음 | 중단, GPT 재생성 금지 |
| AUTH_OR_QUOTA | 인증·결제·한도 문제 | 중단 |
| RESULT_UNKNOWN | 생성 요청 결과 불명확 | 작업 조회 우선, 새 요청 금지 |
| TIMELINE_INVALID | 시간·큐 연결이 깨짐 | 음성·영상 진입 차단 |
| LOCATION_ACTIVITY_CONFLICT | 현재 화면의 활동과 장소 용도 충돌 | 해당 씬의 지정 필드 보정 |
| LOCATION_REFERENCE_MULTIPLE | 장소 참조 여러 개 | 등록 자산과 씬의 목적지를 확인해 하나 선택, 모호하면 중단 |
| LOCATION_ACTIVITY_UNCERTAIN | 현재 활동을 확정하기 어려움 | 경고 또는 제한된 검수, 무조건 실패 금지 |
| EDITORIAL_ADVISORY | 복도 생략·휴식·대화·표현 취향 | 기록 후 진행 |

이 표는 목표 계약이다. 구현과 연결 테스트를 통과하기 전까지 적용 완료로 표시하지 않는다.

## 보정 권한

- 일반 씬 검수기는 기존처럼 image_prompt/camera/lighting/motion_prompt/transition의 텍스트만 변경한다.
- 구조 보정은 일반 검수기와 별도 API/모듈로 분리한다. 허용된 오류 코드와 필드만 변경하며, 서버가 등록 자산 여부와 인접 씬 연속성을 재검증한다.
- reference_ids의 장소 하나 선택과 sequence의 잘못된 이동 설명 보정은 별도 구조 보정 경로에서만 수행한다. 일반 리뷰 응답으로 권한을 확대하지 않는다.
- 정상 씬, 씬 ID·순서·시간, 캐릭터 정체성·버전, 확정 내레이션·자막은 잠근다.
- 부분 보정 최대 3회, 복구 가능한 확정 실패만 신규 프로젝트 최대 2회. 사용자 중지·설정 변경·자산 누락·결과 불명확은 재시작보다 우선한다.
- 1차 계획의 장소 선택부터 같은 정책을 전달한다. 검증 기준은 JSON 설정과 사례 테스트에서 관리하고 프롬프트에 서로 다른 규칙을 중복 관리하지 않는다.

## 안전과 배포

- 진행 중 자동제작·대본 작업이 있으면 API/워커를 재시작하지 않는다.
- 제출 응답이 불명확하면 자동 재제출하지 않는다. 조회 실패를 제작 실패로 간주해 신규 프로젝트를 생성하지 않는다.
- 단계별 커밋·푸시를 남긴다. 롤백은 해당 커밋의 변경을 되돌리는 방식으로 하고 DB·자산은 삭제하지 않는다.
- 비밀값·원본 API 응답을 브라우저나 Git에 노출하지 않는다. 진단은 서버 소유 로그로 남긴다.
- 대기 시간·비용·완료율은 실제 측정한다. 3회 보정이 성공을 보장한다고 안내하지 않는다.
